# 간결한 UI와 메인 화면 PPT 탐색

2026-10-09, codex/compact-ui-file-browser 브랜치에서 구현했다.

## 메인 화면 탐색

좌상단 ‘폴더’ 또는 Ctrl+O로 최상위 폴더를 지정한다. **이 단계에서만 별도의 폴더 선택 창을 연다.** 기본 위치는 Windows에 설정된 바탕화면이며 QStandardPaths.DesktopLocation으로 리디렉션 경로를 따른다. 지정한 경로는 상단에 표시하고 전체 경로를 툴팁으로 제공한다.

메인 화면 왼쪽 사이드바에는 최상위 폴더의 자식부터 표시한다. 폴더와 PPTX·PPTM이 같은 트리에 나타나고 다른 파일과 Office 잠금 파일(~$)은 숨긴다. 폴더를 클릭하면 하위 항목이 그 아래에 펼쳐진다. 하위 폴더를 이어서 선택해도 추가 창을 열지 않는다. PPT를 클릭하면 기존 썸네일 워커에서 읽고 오른쪽 슬라이드 미리보기를 표시한다. 이미 읽은 파일을 다시 선택할 때는 로드된 결과를 사용한다.

트리의 읽은 원본에는 슬라이드 수·상태 아이콘을 표시한다. Ctrl·Shift 다중 선택으로 원본을 제거하거나 다시 읽을 수 있다. ‘원본’ 탭에는 읽은 파일 목록을 유지하며, 최상위 폴더 밖에서 끌어 놓은 파일도 다시 선택할 수 있다. 최상위 폴더를 바꿔도 기존 원본과 출력 순서는 유지한다. 제거·비우기는 앱의 읽은 원본 목록에만 적용하고 실제 파일은 삭제하지 않는다.

사이드바의 검색은 최상위 폴더와 모든 하위 폴더의 PPT **파일명**을 대상으로 한다. 300ms 입력 지연 후 별도 QThread에서 검색하고 상대 경로와 전체 경로 툴팁을 표시한다. 검색 결과를 선택해도 같은 메인 화면의 미리보기로 연결한다. 검색 목록의 원본 아이콘은 Windows의 PPT 파일 연결 아이콘을 사용하며 아이콘을 가져올 수 없으면 주황색 P 아이콘을 사용한다. 읽기 중·완료·실패·취소 상태는 트리 및 원본 목록과 같은 아이콘으로 갱신한다. 완료된 항목에는 체크와 슬라이드 수가 표시되고 상태·상세 안내는 툴팁과 접근성 이름으로 제공한다. 재검색할 때도 기존 상태를 복원하며 원본을 제거하거나 비우면 PPT 아이콘으로 되돌린다. 트리와 검색 목록의 파일 읽기는 실제 클릭 또는 방향키 이동·Enter로만 요청한다. 포커스 복원이나 모델 갱신으로 Qt가 자동 선택한 항목은 원본으로 추가하지 않는다. 검색어를 지우면 선택했던 PPT의 트리 위치와 미리보기를 유지하며, 다른 결과나 트리의 첫 항목을 자동으로 읽지 않는다. 검색어·최상위 폴더가 바뀌면 이전 검색을 취소하고 늦게 도착한 결과를 무시한다.

검색은 대소문자를 구분하지 않으며 최대 2,000개 결과를 표시한다. 접근할 수 없는 항목은 건너뛰고 개수를 표시한다. 심볼릭 링크와 Windows 연결 폴더는 검색에서 순회하지 않는다. 파일 시스템 모델은 비동기로 읽고 검색 결과의 모델 갱신은 GUI 스레드의 큐로 전달한다. 앱 종료 시 검색과 PowerPoint 작업에 취소를 요청하고 이벤트 처리를 계속하며 모든 작업 스레드가 끝난 뒤 닫는다.

## 간결한 도구

파일 제거·비우기·다시 읽기와 출력 삭제·복제·순서 이동을 아이콘으로 표시한다. ‘폴더’와 ‘PPT 생성’은 짧은 문구를 유지한다. 반복 안내는 툴팁과 도움말로 옮겼으며 기능 이름·단축키·접근성 이름을 제공한다. 오류·취소·진행 상태는 계속 표시한다. PPT 생성·복사·COM 관리 코드는 변경하지 않았다.

## 검증

전체 단위 테스트 **128개 통과**: 기존 98개와 파일 검색·메인 사이드바 검증 30개. 신규 검증은 tests/unit/test_file_browser.py에 있다. 루트 폴더 선택·취소, 같은 트리에서 여러 단계 폴더 펼치기, PPT 클릭과 기존 워커 연결, 중복 로드 방지, 다중 선택, 제거 후 재선택, 루트 변경 시 출력 유지, 외부 파일 목록, 검색 중 파일 추가의 트리 복귀, 재귀 검색·한글·대문자 확장자·잠금 파일 제외·접근 실패·연결 폴더·검색 한도·이전 결과 무시·검색 종료 응답성을 확인했다. 검색은 작업 스레드에서 실행되고 결과 행 추가는 GUI 스레드에서 실행되는 것도 검증했다. 검색 아이콘의 파일 연결 정보 사용, 읽기 완료 체크·슬라이드 수·툴팁 갱신, 재검색 상태 복원, 제거·비우기 시 상태 해제, 취소 후 재읽기와 실패 표시를 추가 검증했다. 복수 검색 결과에서 포커스 이동·검색 지우기 버튼이 다른 파일을 추가하지 않는지, A.pptx와 한글 A.pptx 중 클릭한 경로만 남는지, 검색 해제 시 선택 위치와 미리보기 유지, 방향키·Enter 선택 동작도 검증했다. 전체 테스트는 22.064초에 통과했다.

화면 검증은 기존 실제 PPT 캐시만 사용해 수행한다. 다음 명령은 COM을 실행하지 않으므로 tests/fixtures/basic/A.pptx와 B.pptx의 유효한 캐시가 필요하다.

~~~powershell
$env:QT_QPA_PLATFORM = 'windows'
.\.venv\Scripts\python.exe -X utf8 scripts\validate_file_browser.py
~~~

실제 Windows 메인 화면의 1600×900·1000×640 배치, 폴더 클릭·PPT 선택·미리보기, 검색 결과의 PPT 아이콘과 클릭 후 체크·슬라이드 수, 검색어 해제 시 원본 수·선택 유지, 탐색 중 모달 창 없음은 output/file_browser_validation_b65lz55f/report.json에서 통과했다. 클릭 전·후 및 검색 해제 PNG(main_search_before.png·main_search_ready.png·main_search_cleared.png)는 같은 폴더에 기록했다.

사용자가 지정한 C:/Work/Side Project/ppt_merge를 실제 최상위 경로로 설정한 검색·클릭·검색 지우기 검증도 통과했다. 실제 파일 시스템의 A.pptx 검색 결과 6개 중 tests/fixtures/basic/A.pptx만 클릭했으며, 검색 해제 전후 원본 수는 1개로 유지되었다. 선택 이벤트와 경로 기록은 output/search_clear_reproduction.json에 있다. 이 재검증의 PPT 로드는 테스트 서비스로 수행해 COM을 사용하지 않았다.

최신 실행 파일은 dist/search-clear/PPTMerge.exe에 별도로 빌드했다. 실제 Office 썸네일 8장 로드, A2 → B4 → A1 → A2 생성, 40장 생성 중 종료·취소·PowerPoint 정리 등 19개 조건이 통과했다. 최신 보고서는 output/package_validation_pvloujlv/report.json이며 종료 코드 0, 총 21.77초, 남은 PowerPoint 프로세스 없음으로 확인했다. 바이너리 정보와 재검증 방법은 [EXE 패키징](exe_packaging.md)에 있다.
