# 간결한 UI와 앱 내 PPT 탐색

2026-10-09, `codex/compact-ui-file-browser` 브랜치에서 구현했다.

## 화면 변경

- 파일 제거·목록 비우기·다시 읽기와 출력 삭제·복제·순서 이동을 아이콘으로 표시한다.
- ‘추가’와 ‘PPT 생성’은 핵심 작업이므로 짧은 문구를 유지한다.
- 반복 안내를 툴팁과 상단 도움말 버튼으로 옮겼다. 오류·취소·진행 상태는 계속 표시한다.
- 아이콘 버튼에는 기능 이름·단축키 툴팁과 접근성 이름이 있다. 기존 단축키와 드래그 동작을 유지한다.
- 원본 목록은 파일명·슬라이드 수를 표시하고 상태 아이콘과 툴팁으로 상세 정보를 전달한다.

## 파일 추가

‘추가’ 또는 Ctrl+O로 앱 내부 탐색 화면을 연다. 기본 시작 위치는 Windows의 바탕화면이다. `QStandardPaths.DesktopLocation`을 사용하므로 Windows에서 설정한 리디렉션 경로를 따른다.

상단에서 바탕화면·문서·다운로드·홈으로 이동하거나 폴더 버튼으로 다른 시작 폴더를 선택한다. 트리에서 폴더를 펼쳐 PPTX·PPTM 파일을 선택하고 ‘추가’를 누른다. Ctrl·Shift 다중 선택과 파일 더블클릭을 지원한다. 마지막 시작 폴더는 앱을 실행하는 동안 기억한다.

검색은 현재 시작 폴더와 그 하위 폴더의 **파일명**을 대상으로 한다. 대소문자를 구분하지 않으며 PPTX·PPTM만 표시한다. 결과에는 시작 폴더 기준 상대 경로와 전체 경로 툴팁을 표시한다. 검색어를 지우면 트리로 돌아간다. 검색어를 입력한 뒤 300ms 동안 변경이 없으면 작업을 시작한다.

파일 시스템 트리는 Qt의 비동기 모델을 사용하고 검색은 별도 QThread에서 실행한다. 검색어나 시작 폴더가 바뀌면 이전 작업에 취소를 요청하고 이전 결과를 무시한다. 대화상자를 닫으면 실행 중인 검색을 취소한 뒤 스레드 종료를 기다리며 GUI 이벤트 처리를 계속한다.

검색에서 접근할 수 없는 항목은 건너뛰고 개수를 표시한다. 심볼릭 링크·Windows 연결 폴더는 순회하지 않고 Office 잠금 파일(`~$`)은 검색 결과에서 제외한다. 결과는 최대 2,000개로 제한하며 한도에 도달하면 검색어를 좁히라는 안내를 표시한다. 선택 이후 파일이 삭제되면 추가를 막는다. 파일 선택 결과는 기존 `add_sources`와 썸네일 워커로 전달한다. PPT 생성·복사·COM 관리 코드는 변경하지 않았다.

## 검증

전체 단위 테스트 **115개 통과**: 기존 98개와 신규 17개. 신규 테스트는 `tests/unit/test_file_browser.py`에 있다. 하위 폴더·한글·대문자 확장자 검색, 검색 범위, 다중 선택, 폴더 선택 제한, 삭제된 파일, 접근 실패 격리, 연결 폴더 제외, 결과 한도, 이전 결과 무시, 검색 취소·종료 응답성, Windows 바탕화면 시작 위치, 기존 워커 연결과 단축키를 검증한다.

화면 검증은 다음 명령으로 기존 실제 PPT 캐시만 사용해 수행한다. COM을 실행하지 않으므로 `tests/fixtures/basic/A.pptx`와 `B.pptx`의 유효한 캐시가 필요하다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\validate_file_browser.py
```

검증 산출물은 매번 별도 `output/file_browser_validation_*` 폴더에 기록한다. 1600×900·1000×640 메인 화면, 폴더 트리, 검색 결과를 PNG로 저장하고 실제 모달 파일 선택까지 검증한다.

이번 Windows 실제 화면 검증은 `output/file_browser_validation_hndy7yzi/report.json`에서 모두 통과했다. 폴더·PPT 아이콘과 검색 결과 배치를 육안으로 확인했다.

업데이트한 `dist/PPTMerge.exe`를 별도 한글 배포 폴더에서 실행한 검증도 통과했다. 실제 Office에서 썸네일 8장 로드, A2 → B4 → A1 → A2 생성, 40장 생성 도중 창 닫기·취소·PowerPoint 종료 등 19개 조건을 확인했다. 종료 코드 0이고 남은 PowerPoint 프로세스는 없었다. 보고서는 `output/package_validation_mi8uw71_/report.json`이다. 새 파일 탐색 화면의 기능 검증은 위 소스 UI 테스트와 Windows 화면 검증으로 수행했다.
