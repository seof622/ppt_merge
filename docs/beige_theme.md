# 베이지 테마

2026-10-17, 데스크톱 앱 디자인을 검색한 뒤 크림·오트밀·브라운 계열로 변경했다.

## 디자인 참고

- [Craft Customize](https://www.craft.do/customize): Sand 스타일과 문서 작업 공간의 차분한 표면 구분을 참고했다.
- [Dribbble beige dashboard](https://dribbble.com/search/beige%20dashboard?timeframe=year): 베이지 UI의 패널 구분·카드·강조색 구성 사례를 조사했다.

참고 자료를 바탕으로 이 앱의 파일 탐색·원본 슬라이드·출력 순서 구조에 맞춰 색상을 직접 구성했다.

| 용도 | 색상 |
|---|---|
| 앱 바깥 프레임 | `#e7ddce` 웜 베이지 |
| 폴더 탐색 | `#e6dac7` 오트밀 |
| 원본 목록 | `#f0e7db` 아이보리 |
| 슬라이드·결과물 작업 공간 | `#faf7f1` 크림 |
| 카드 | `#fffdf8` 종이색 |
| 선택 배경 | `#e9dcc8` 샌드 |
| 주요 버튼·드롭 표시 | `#78583e` 브라운 |
| 본문 | `#3d352e` 짙은 웜 브라운 |

`src/ui/theme.py`에서 스타일시트와 Qt 팔레트를 관리한다. Windows의 기본 선택색이 목록과 기본 컨트롤에 섞이지 않게 팔레트도 적용했다. 일반·비활성·마우스 반응 아이콘과 결과 파일 열기 버튼에도 같은 색상군을 사용한다. 검색·선택·키보드 포커스·누름·비활성 상태는 배경과 테두리로 구분한다.

작은 창에서 결과물 카드의 파일명과 번호가 잘리는 문제도 수정했다. 출력 목록 높이에 따라 카드와 썸네일을 줄이고, 좁은 높이에서는 `출력 순서 · #원본 번호 · 파일명`을 한 줄로 표시해 파일명이 생략되어도 순서와 번호를 먼저 확인할 수 있다. 큰 창의 두 줄 표시는 유지한다.

후속으로 패널 사이의 굵은 가로·세로 구분선을 제거했다. splitter의 표시 폭을 4px에서 1px로 줄이고 기본 배경을 투명하게 했으며, 마우스를 올렸을 때만 연한 샌드색으로 표시한다. Qt가 얇은 splitter 주변으로 드래그 영역을 확장하므로 크기 조절과 하단 접기 동작은 유지된다. 결과물 패널 위의 중복 테두리도 제거해 패널 배경색 차이로 영역을 구분한다.

구분선 조정 후 `test_output_collapse` 4개와 `test_output_ui` 10개를 다시 실행해 통과했고, 두 창 크기에서 렌더링을 재확인했다. 이 단계의 화면은 `output/beige_soft_dividers_1600.png`이다.

## 사용자 참고 이미지 반영

사용자가 제공한 3열 데스크톱 앱 이미지를 참고해 폴더 탐색·PPT 목록·오른쪽 작업 공간의 세 열이 화면 아래까지 이어지도록 재배치했다. 결과물 미리보기와 생성 버튼은 오른쪽 작업 공간 안에 둔다. 따라서 결과물을 접거나 펼쳐도 왼쪽 두 열의 높이는 바뀌지 않는다.

앱 바깥에 여백을 두고 외곽 모서리를 둥글게 처리했다. 왼쪽의 오트밀색에서 가운데 아이보리색, 오른쪽 크림색으로 이어지며, 상단 브랜드·도구와 하단 상태 표시는 바깥 프레임에 통합했다. 참고 이미지의 구성을 베이지 팔레트에 맞춰 적용한 것이다.

작업 공간 너비가 680px보다 작으면 앞으로·뒤로·맨 앞으로·맨 뒤로 이동을 ‘순서 이동 메뉴’에 모은다. 같은 QAction을 사용하므로 단축키와 우클릭 메뉴도 유지된다. 넓어지면 개별 아이콘이 다시 표시된다.

## 검증

- UI 회귀 테스트 76개: `test_ui` 9개, `test_file_browser` 32개, `test_output_ui` 10개, `test_ux` 11개, `test_generation_ui` 7개, `test_output_collapse` 4개, `test_workspace_layout` 3개. 각 모듈을 별도 Python 프로세스로 실행했다. 새 레이아웃 검증은 왼쪽 두 열의 높이 유지, 좁은 작업 공간의 메뉴 이동 명령, 1000×640에서 생성 후 열기 버튼과 접기 상태의 배치를 확인한다.
- 실제 Qt offscreen 렌더링으로 1600×900·1000×640의 기본·선택·접기·복원·빈 화면·검색·드롭 위치·진행률·메뉴 상태를 확인했다. 이미지 검토 자료는 `output/beige_*.png`, 보고서는 `output/beige_ui_report.json`이다.
- 기존 캐시를 이용한 파일 탐색·검색·PPT 선택·슬라이드 담기 검증 스크립트도 통과했다. 보고서: `output/file_browser_validation_0b3s2dcq/report.json`. 서로 다른 부모 위젯에 있는 패널의 배치 검증은 창의 공통 좌표계에서 수행하도록 수정했다.
- 렌더링에는 기존 테스트 자료의 PNG 캐시를 사용했다. PowerPoint COM 병합 엔진은 변경하지 않았으며 실제 Office 통합 검증은 이번에 재실행하지 않았다.
- 배포 파일을 기존 경로인 `dist/PPTMerge.exe`로 빌드했다. EXE 내부에 테마와 최종 카드 표시 코드가 포함된 것을 확인했고, `--help`로 앱 모듈을 가져오는 시작 검증이 종료 코드 0으로 통과했다. 이 검증은 EXE의 실제 화면 조작 검증을 의미하지 않는다.

테스트 로그: `output/reference_test_*.log`. 최종 화면: `output/beige_reference_1600.png`, `output/beige_reference_1000.png`. 빌드 로그: `output/beige_build.log`.
